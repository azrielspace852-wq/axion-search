AXIONSearch

Documentation

AXION Search uses a separate Cloudflare Pages website and API Worker. The Pages project forwards its API routes to the Worker via the AXION_SEARCH_API Service binding.

Production URLs

Website: https://search.xxn.cc.cd

API: https://api.search.axn.cc.cd

Repository layout

pages/    Static UI, SDK, Pages Functions, wrangler.jsonc
workers/  Fetch API Worker, search engine, wrangler.jsonc

Cloudflare architecture

Browser → Pages: search.xxn.cc.cd
              └─ /api/* and /health Pages Functions
                     └─ AXION_SEARCH_API Service binding
                              ↓
                        Worker: axion-search-api
                        api.search.axn.cc.cd
                              ├─ search provider orchestration
                              └─ Google AI Studio Gemma 4 streaming

Production does not use Cloudflare Tunnel, VPN, or proxy settings. Worker and Pages are deployed separately; Pages calls the Worker over the internal service binding.

Deploy

  1. Install Wrangler and authenticate with npx wrangler login.
  2. Run checks: npm test.
  3. Deploy API first: npm run deploy:api.
  4. Configure at least one Worker Secret named GOOGLE_AI_STUDIO_API_KEY_1. Optional rotating keys are GOOGLE_AI_STUDIO_API_KEY_2 and GOOGLE_AI_STUDIO_API_KEY_3. Optional Brave provider key: BRAVE_API_KEY.
  5. Deploy Pages: npm run deploy:pages.
  6. Configure Worker custom domain api.search.axn.cc.cd, Pages custom domain search.xxn.cc.cd, and service binding AXION_SEARCH_API → axion-search-api.

Secrets belong in Workers & Pages → the axion-search-api Worker → Settings → Variables and Secrets → Secrets. Never put API keys in static JavaScript, Pages public variables, or the repository. GitHub auto-deploy needs only CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID as repository secrets.

Search API

GET https://api.search.axn.cc.cd/api/v1/search?q=kucing&type=all&safe=1&lang=id
# Types: all | web | images | videos | news | audio | apps | shop | axion

Blank type and legacy type site default to all. The website also starts on All.

Live AI summary

curl -N -X POST "https://api.search.axn.cc.cd/api/summary?stream=1" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{"q":"Apa itu AXION?","lang":"id","safe":true,"ai":true}'

Live AI chat

curl -N -X POST "https://api.search.axn.cc.cd/api/v1/chat?stream=1" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{"messages":[{"role":"user","content":"Apa itu AXION?"}],"lang":"id","safe":true}'

Both endpoints use Server-Sent Events. Clients receive live meta, delta, and complete events. Model choice is not accepted from users or SDK request bodies.

Google AI Studio model/key policy

The Worker rotates between only gemma-4-31b-it and gemma-4-26b-a4b-it; there is no model selector. A request starts with the next model in the isolate's round-robin sequence, and model/key fallback is attempted when a provider request fails. Google lists both IDs as supported Gemma models for the Gemini API in its official Gemma API documentation.

JavaScript SDK

<script src="https://search.xxn.cc.cd/sdk/axion-search-sdk.js"></script>
<script>
  const axn = new AxionSDK();
  const results = await axn.search('kucing', { type: 'all', lang: 'id' });
  await axn.summaryStream('jelaskan neural network', { lang: 'id' }, event => {
    if (event.type === 'delta') console.log(event.text);
  });
  await axn.chatStream([{ role: 'user', content: 'Jelaskan AXION' }], { lang: 'id' }, event => {
    if (event.type === 'delta') console.log(event.text);
  });
</script>

See SDK & Integrations for the complete method list. The SDK supports separate apiBase/siteBase origins and is dependency-free.

CPU budget and data storage

Worker and Pages Functions configs set the CPU budget to 10 ms. The active code uses bounded response reads, lightweight parsers, limited provider fan-out, and supplied search results for AI summaries to avoid redundant scraping. Network waiting is not counted as CPU, but HTML parsing and JSON work are. Actual CPU usage must be confirmed in Cloudflare Metrics after deployment.

Search history is saved in IndexedDB and migrated from the legacy localStorage history key once. Theme, language and small settings remain in localStorage. Settings supports JSON export/import and clearing search history.
