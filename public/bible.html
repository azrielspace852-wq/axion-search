AXIONSearch

Product Bible DRAFT v0.3

The founding principles, non-goals, and decision record of AXION Search. Draft — open to revision.

Chapter 1 — Mission

AXION Search exists to give everyone a search engine they can trust. Trust means: you know what is collected (nothing), you know where your data lives (your device), and the answers you get are grounded in real sources — not invented.

Chapter 2 — First principles

  1. Privacy is the default, not a setting. No accounts, no logs, no profiles. If a feature requires tracking, it does not ship.
  2. Speed is a feature. Results must start rendering in under 1s. Provider rotation exists partly to keep latency low.
  3. AI must be grounded. A confident wrong answer is worse than no answer. The AI says "I don't know" when the snippets don't cover it.
  4. The user owns their data. Export/import must be one click. No lock-in, ever.
  5. Open by default. Self-hostable, documented, SDK-first. The search index of the AXION ecosystem (*.axn.cc.cd) is a public good.

Chapter 3 — Non-goals

  • We will not build an ad business. No ads, ever.
  • We will not build a user profile to "personalize" results. Personalization = local settings only.
  • We will not show which provider answered a query (except in the privacy policy, for transparency).
  • We will not log queries. In-memory only, discarded per request.

Chapter 4 — Decision record (ADR)

ADR-001: GitHub Actions + Cloudflare Tunnel (legacy)

Historical decision: the original Node deployment used a self-chaining GitHub Actions loop and Cloudflare Tunnel. This remains archived for legacy Node/VPNX use, but it is superseded for production hosting by ADR-004. It is no longer the active Cloudflare deployment architecture.

ADR-002: Scrape over paid search APIs

Decision: rotate public endpoints (Google/Bing/DDG/Mojeek/YouTube/News RSS/iTunes) instead of paid APIs. Consequences: free at scale, but providers may block; rotation + merge mitigates. Paid backends (Brave/SerpAPI) planned as optional v4.4.

ADR-003: Stateless server, stateful browser

Decision: all user state in localStorage + functional cookies. Consequences: trivial horizontal scaling, perfect privacy, device portability via JSON export.

ADR-004: Cloudflare Pages + Workers with a Service binding

Context: the app needs a static website and an independently scalable API without a long-running Node process. Decision: host public assets and Pages Functions on search.xxn.cc.cd; deploy the Fetch-based API Worker on api.search.axn.cc.cd; connect Pages to Worker through the AXION_SEARCH_API service binding. Keep API routes and the JavaScript SDK backward-compatible. Consequences: no Express server or Cloudflare Tunnel is required in production; Node-only outbound proxy environment variables do not apply to Workers native fetch(), so the proxy-backed legacy deployment remains archived separately.

Chapter 5 — Voice & tone

AXION speaks plainly. No marketing fluff. Errors are honest ("Provider blocked, trying next…"). The AI cites sources. The UI is calm, dark-first, fast. The logo gradient (cyan→blue→emerald) is the only brand flourish.

Chapter 6 — Success metrics

  • Uptime ≥ 99% (self-chain + safety net).
  • Query success rate ≥ 95% (at least one provider answers).
  • AI hallucination rate: measured by spot-check; target 0% factual claims outside snippet context.
  • Time-to-first-result < 1.5s p95.
This Bible is a draft. Propose changes via the repository. Principles are hard; tactics are soft.
