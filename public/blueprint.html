The technical blueprint of AXION Search v3 — layers, data flow, and invariants.

Provider orchestration invariants

  1. Rotation: start index = (minute-of-hour) mod N — distributes load, avoids hammering one source.
  2. Fallback: on block/empty/timeout, move to next provider. Never fail a query while any provider still works.
  3. Merge for richness: concatenate results from up to 3 providers, de-duplicate by URL, cap at 30.
  4. SafeSearch: applied at query time (negative terms) and again on results (blocklist filter).
  5. AXION priority: if query matches AXION keywords, prepend site:axn.cc.cd results.
  6. No provider identity leaks to the frontend — the engine field is never returned. Only privacy page names them.

AI invariants (anti-hallucination)

  1. Prompt contains only search snippets + query. No world knowledge assumed.
  2. Explicit instruction: if context lacks the answer, say so — never invent.
  3. Temperature fixed at 0.1; max 600 output tokens.
  4. Citations required ([1], [2]…). Model selectable from allowlist only.
  5. 3 keys round-robin; 429 → immediate failover to next key.

24/7 hosting invariants

  1. Job lifetime < 350 min (always under GitHub's 6h hard limit).
  2. Self-chain dispatch at T-60 min via PAT; cron safety-net every 30 min.
  3. New job waits (health poll) for old origin to release port; cloudflared runs HA so tunnel never drops.
  4. All secrets written from env to file with printf — never echoed. SILENT=1 mutes server logs.

Data invariants

  1. User data (settings, history) lives only in browser localStorage. Server is stateless.
  2. Cookies are functional only (lang/safe/theme), 1-year max-age, SameSite=Lax.
  3. Export/import is a single JSON file — full device portability.
