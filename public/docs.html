AXIONSearch

Documentation

AXION Search is a meta-search frontend deployed to Cloudflare Pages with a separate API Worker. The website calls the API through a Pages Service binding; external applications use the API domain.

Production URLs

Website: https://search.xxn.cc.cd

API: https://api.search.axn.cc.cd

Cloudflare architecture

Browser
  ├── Pages: search.xxn.cc.cd
  │     ├── static HTML / CSS / JavaScript
  │     └── Pages Functions /api/* and /health
  │                │
  │                └── Service binding: AXION_SEARCH_API
  │                              │
  └── SDK / external clients ────┤
                                ▼
                     Worker: axion-search-api
                     api.search.axn.cc.cd
                       ├── Provider orchestration
                       ├── SafeSearch and result filtering
                       ├── JSON public API v1
                       └── Grounded AI summary/chat

The Pages project is configured in wrangler.pages.jsonc. The Worker is configured in worker/wrangler.jsonc. The service binding is named AXION_SEARCH_API and targets the Worker service axion-search-api.

Deploy

  1. Install dependencies with npm install and authenticate using npx wrangler login.
  2. Deploy the API Worker first: npx wrangler deploy --config worker/wrangler.jsonc.
  3. Add Worker secrets with npx wrangler secret put AI_KEY_1 --config worker/wrangler.jsonc. Repeat for AI_KEY_2, AI_KEY_3, and optionally BRAVE_API_KEY.
  4. Deploy the Pages site: npx wrangler pages deploy ./public --project-name axion-search-site --config wrangler.pages.jsonc.
  5. Attach the custom domains api.search.axn.cc.cd to the Worker and search.xxn.cc.cd to Pages. Verify the Pages service binding AXION_SEARCH_API points to axion-search-api.

For automatic deploys from GitHub, see .github/workflows/deploy-cloudflare.yml. Set the repository secrets CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID. AI keys stay in Cloudflare Worker secrets.

Search API

GET https://api.search.axn.cc.cd/api/v1/search?q=kucing&type=web&safe=1&lang=id
# Types: web | images | videos | news | audio | apps | shop | axion | all

Compact tool search

GET https://api.search.axn.cc.cd/api/v1/tool/search?q=berita+terbaru
# { query, results: [{ title, url, snippet, source }] }

AI summary

GET https://api.search.axn.cc.cd/api/summary?q=...&model=gemini-2.5-flash&lang=id

AI chat

POST https://api.search.axn.cc.cd/api/v1/chat
Content-Type: application/json
{
  "messages": [{ "role": "user", "content": "Apa itu AXION?" }],
  "model": "gemini-2.5-flash",
  "lang": "id",
  "safe": true
}

Legacy-compatible endpoints

GET /api/search and GET /api/summary remain available for existing integrations. The website itself uses relative /api/* paths which Pages Functions forward through the binding.

JavaScript SDK

<script src="https://search.xxn.cc.cd/sdk/axion-search-sdk.js"></script>
<script>
  const axn = new AxionSDK();
  const results = await axn.search('kucing', { type: 'images', lang: 'id' });
  const summary = await axn.summary('jelaskan neural network', { lang: 'id' });
  const chat = await axn.chat([{ role: 'user', content: 'Jelaskan AXION' }], { lang: 'id' });
</script>

Configure apiBase, siteBase, and timeout when using custom hosts. The legacy base option is retained for backwards compatibility. See SDK & Integrations for full examples.

Search providers and verticals

Web: DuckDuckGo, Bing, Google (regular/basic), Yahoo, Mojeek, optional Brave. Images: Bing and DuckDuckGo. Videos: Bing and YouTube. News: Google News RSS and Bing News RSS. Audio: iTunes. Apps and shop searches reuse web providers with vertical-specific query modifiers. The AXION type focuses on *.axn.cc.cd and relevant web queries prioritize AXION results.

AI configuration

The Worker supports rotating AI_KEY_1, AI_KEY_2, and AI_KEY_3 secrets. The default model is gemini-2.5-flash; the current allowlist is enforced by the Worker. If no AI key is configured, search continues to work while summary/chat report that AI is not configured.

Runtime compatibility

Cloudflare production uses native Fetch handlers; Express is not used in the Worker. Search provider calls run concurrently and results are merged in rotating provider order. The legacy Node server is retained for users who need its old HTTP/VPNX proxy workflow. Cloudflare Workers native fetch() does not transparently honor HTTP_PROXY or VPNX_PROXY, so the Cloudflare deployment uses Cloudflare egress.

Privacy and browser settings

Theme, language, and search history are stored in browser local storage, with JSON export/import for device migration. SafeSearch is enabled by default and can be turned off by the user. Requests pass query text to selected search providers, and AI requests pass search context to the configured Google AI service.
